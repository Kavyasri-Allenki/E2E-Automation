# WhiteCoats appointment automation

Scenario pack for [myappointments.whitecoats.com](https://myappointments.whitecoats.com), the WhiteCoats healthcare portal. It covers the marketing site and the seven sign-in roles: patient, staff, doctor, branch admin, hospital admin, sales, and super admin.

The full catalog is in [scenarios/SCENARIOS.md](scenarios/SCENARIOS.md). Scenarios marked **automated** run in Playwright against the public site. Scenarios marked **sandbox** are written for a non-production tenant because they sign in, send one-time codes, or change appointments and clinical records.

Public tests never submit a password, never request an OTP, and never create an account. A guard fails the run if a test calls those APIs.

## Run the public suite

```bash
npm install
npx playwright install chromium
npm test
```

Use another host only when it is a sandbox you are allowed to test:

```bash
WC_BASE_URL=https://your-sandbox.example npm test
```

`npm run test:list` prints every automated scenario. `npm run report` opens the HTML report after a run.

## What the public suite checks

- Home page content, feature list, anchors, footer, phone menu, and the not-found page
- Portal picker and each role's sign-in shell
- Client-side email, password visibility, forgot-password, and reset-password checks
- Patient mobile field rules, without sending a code
- Patient signup wizard rules, without creating an account
- Anonymous visitors bounced off dashboards and booking screens

## Super admin sign-in

`tests/auth/super-admin-login.spec.ts` signs in as `superadmin@whitecoats.com` only when `WC_SUPER_ADMIN_PASSWORD` is set. `npm test` skips it otherwise. If the account is already signed in on another device, the scenario confirms that dialog, which ends the other session, then signs out again.

`tests/auth/super-admin-e2e.spec.ts` uses the same sign-in and walks every sidebar screen, searches the tenant list, opens and dismisses Add Tenant without creating anything, views one tenant's details, and signs out. It does not change tenant status, send SMS, or submit a payment.

`tests/auth/super-admin-add-tenant.spec.ts` reads every Add Tenant field, rejects an empty form and invalid values, and creates one clinic (`cursor-e2e`) with Cash if that subdomain is not already there. A later run only opens that tenant. It does not generate a payment link or charge a card. The admin password is generated by the site and addressed to `cursor-e2e-admin@example.com`.

```bash
WC_SUPER_ADMIN_PASSWORD='your-password' \
  npx playwright test tests/auth/super-admin-login.spec.ts tests/auth/super-admin-e2e.spec.ts tests/auth/super-admin-add-tenant.spec.ts --retries=0
```

## Patient video booking

`tests/auth/patient-video-booking.spec.ts` is WC-PAT-VIDEO, a headed scenario. `npm test` skips it unless one of these is set:

- `WC_PATIENT_OTP` — the six-digit code for a fresh SMS login on mobile `7893934952`. The script presses Send OTP, then submits this code.
- `WC_PATIENT_SESSION_FILE` — path to a local JSON session already verified for that mobile number. The script restores the session and does not request a new SMS.

Keep the code, the session file, and any password on the machine that created them. Do not commit them.

The script selects Ayuman Hospitals, opens Dr Amithaa Sai in Dermatology (the name shown on the site), chooses Video Consultation, fills the reason "Video dermatology consultation for a skin review", and takes the first open slot from 4:00 PM through 8:00 PM. The headed run on 14 October 2026 selected Wednesday 14 October 2026 at 4:00 PM, then Pay & Book. Live Razorpay opened for ₹1. The script does not enter a card or any other payment, so the visit stays unconfirmed.

`--headed` needs a display. The spec records video, uses a 1280×800 window, and slows each action by 250 ms.

```bash
WC_PATIENT_SESSION_FILE=/path/to/patient-session.json \
  npx playwright test tests/auth/patient-video-booking.spec.ts --headed --retries=0
```

```bash
WC_PATIENT_OTP='sms-code' \
  npx playwright test tests/auth/patient-video-booking.spec.ts --headed --retries=0
```

## Staff EMR workflow

`tests/auth/staff-emr.spec.ts` signs in on the EMR host, walks every staff screen, checks the fields on those screens, then registers one test patient, books Dr. Kavyaa Allenki (the Kavya doctor on the Sunshine directory), reschedules that visit, creates an invoice, and records a cash payment. `npm test` skips it unless `WC_STAFF_PASSWORD` is set. Point `WC_BASE_URL` at the host you are allowed to change.

The spec records video, uses a 1280×800 window, and slows each action by 250 ms. `--headed` needs a display.

```bash
WC_BASE_URL=https://emr.whitecoats.com \
WC_STAFF_EMAIL='staff@example.com' \
WC_STAFF_PASSWORD='your-password' \
  npx playwright test tests/auth/staff-emr.spec.ts --headed --retries=0 --workers=1
```

## Sandbox scenarios

Book, cancel, reschedule, check-in, billing, EMR, and lead flows are specified in the catalog. WC-PAT-VIDEO is the booking script that runs here, and it stops when Razorpay opens. Run the other flows only against a tenant created for testing, with accounts you own.
